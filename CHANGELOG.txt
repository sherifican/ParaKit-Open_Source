      below used an "<app>-<htmlrev>" form where the trailing "-N" tracked the
      companion Practice/Preview HTML editions; that "-N" was dropped from 4.5.4.3
      on (Practice Mode v2 is no longer updated -- a v3 / Kit Studio is coming in
      the ParaKit v5 rebuild).
    - The earlier .exe line uses a plain "vX.Y.Z" form. The compiled .exe
      currently lags the .py source on purpose (see README.txt); the entries
      below it are the historical release notes carried over from the .exe repo
      (https://github.com/sherifican/ParaKit---Releases).
    - This is the curated history. A handful of very old 4.0-4.4 rapid-iteration
      micro-versions only ever appeared in the in-app log and aren't repeated
      here; everything meaningful is included.

------------------------------------------------------------------------------
  v4.9.10   --   2026-08-01
------------------------------------------------------------------------------
  Bug fixes across the MIDI Editor, Spectral Comparison, Preview, the YouTube
  tab, the Stem Splitter and batch conversion. No detection changes.

  REVIEW ISSUES NO LONGER FIXES THE WRONG NOTES
  The MIDI Editor's Review Issues window remembered the notes it found by
  POSITION. That window is meant to be used while you edit the chart behind it
  -- that is what Select & Jump is for -- so if you deleted, sorted or undid
  anything before pressing Auto Fix, every position had shifted and Auto Fix
  acted on whatever note had moved into that slot instead. It now remembers the
  notes themselves. If the chart has changed so much that a scan is stale, it
  tells you to rescan instead of quietly doing nothing.

  TWO TABS CAN NO LONGER OVERWRITE EACH OTHER'S WORK
  Spectral Comparison's Overwrite and the MIDI Editor's Save could both write
  the same file. Whichever you used second silently threw away the other's
  corrections. Each now tells the other, so the editor reloads (or asks first if
  you have unsaved edits), and saving in the editor disables an Overwrite that
  would write a stale comparison back over it.

  UNSAVED EDITS ARE NO LONGER LOST WITHOUT WARNING
  Sending a chart from the MIDI Editor to Preview loaded the SAVED file, so
  unsaved edits silently did not appear -- it now offers to save first. Preview
  itself no longer replaces an edited chart when you load the demo, import
  another chart, clear it, or receive one from another tab, without asking.

  AUDIO NO LONGER KEEPS PLAYING AFTER PREVIEW CLOSES
  Closing Preview cancelled its timers but never stopped playback, so the song
  could keep playing with nothing left on screen to stop it. Preview now stops
  the audio first, then closes.

  YOUTUBE LIBRARY
  When a download finished without reporting its file name, ParaKit fell back to
  the newest audio file in the folder no matter how old it was, then wrote the
  requested song's title, artist and cover onto it -- silently relabelling an
  unrelated earlier download. It now only considers files from that download.
  A corrupted Deno download could also be reported as "Deno detected" while the
  button to re-download it was disabled; it is now validated before being kept.

  STEM SPLITTER
  The model-status line was written by two checks racing each other, so "models
  ready" could be replaced a moment later by "models not cached". Frozen builds
  running DrumSep also ignored the graphics-card check and could crash on newer
  cards instead of falling back to the CPU.

  DISK SPACE
  Stem-splitting and pre-split leftovers were written under names the temp
  sweep did not recognise, so a run that crashed part-way left files behind
  that nothing ever cleaned up. They are now named so the sweep can find them,
  and anything a crash leaves behind is cleared on the next start.

  BATCH CONVERSION
  An unexpected error left the progress bar spinning and the button stuck on
  "Converting..." forever, with nothing reported. It now says what happened.

  Later fix rounds in the same release, below, extend to Sheet Music, the
  Practice tab, the Song Tester, the Song Creator, the Asset Manager, the
  .ogg converter, the MIDI Extractor and the Help tab.

  SHEET MUSIC: TIMING
  Four timing defects, covering both conversion modes:
  - Auto-align (Basic mode) applied the typed offset in the wrong units, so
    it was only correct for files that happened to use 480 divisions per
    quarter note. A typed 2.5-second offset could land at 1200 seconds on one
    file and 1.6 on another; Sibelius and Finale exports were both affected.
    The offset now lands exactly where entered, as the label promises.
  - In the default (high-accuracy) mode, a pickup bar pushed the whole song
    late: every note after the lead-in played late by the length of the
    missing beats, on a bar layout that is routine for MuseScore scores.
    Measures now advance by their actual content.
  - "Override Time Sig" did nothing in the default mode, and every exported
    file claimed 4/4 whatever the score said. A 6/8 score now writes 6/8,
    and the override is honoured in both modes.
  - Scores with more than one instrument could come out stretched in Basic
    mode: the drum part was timed with the FIRST part's resolution (say, the
    piano's), so drum onsets could play at several times their real spacing.
  Also: notes pushed before 0:00 by a negative offset were silently stacked
  into one chord at the very start -- the number clamped is now reported --
  and the log line reporting the offset printed +0.000s no matter what was
  typed.

  SHEET MUSIC: .MXL FILES, SILENT OVERWRITES, MISSING FFMPEG
  - A compressed .mxl whose score member is named "score.musicxml" --
    spec-legal, and what common exporters produce -- failed to convert:
    "Could not find XML content" in Basic mode, and in the default mode a
    crash naming an internal Python variable, right after a log line saying
    a step had been harmlessly skipped. Both modes read these files now.
  - Both modes wrote "<score name>.mid" into the remembered output folder
    without asking, so two sources sharing a file name silently replaced
    each other's chart. It now asks before overwriting; declining saves
    alongside under a numbered name instead of throwing away a conversion
    that already ran.
  - On a machine without FFmpeg, audio conversion failed with one
    "[WinError 2] The system cannot find the file specified" per file --
    wording that reads as "your input file is missing". FFmpeg is now
    checked before any file is touched and the install guidance, with the
    download link, is actually shown. Installs with a bundled ffmpeg.exe
    still convert as before.
  - The Polish word for the kick drum was stored garbled in the
    instrument-name table, so the advertised Polish instrument-name
    correction could never match it.
  - Every conversion log ended with a stray duplicate of the last
    per-instrument count line.

  PRACTICE: CALIBRATION MEASURED THE WRONG THING
  The latency calibration overlay said "tap along with the metronome click"
  -- and never started a metronome; it only clicked back in response to each
  tap. The number it produced measured how STEADILY you tap, not how LATE: a
  perfectly steady tapper scored about 0 ms whatever their real latency was,
  and that value shifts how your hits are judged. A real metronome click now
  plays at a fixed tempo and each tap is measured against it; taps too far
  from any click to be attributed are dropped rather than guessed at, and
  the click stops when the overlay closes.

  A second defect in the same test surfaced after that fix: the click ran
  twice a second, so any real delay past a quarter second matched the NEXT
  click instead of its own -- with the wrong sign. A true +300 ms delay
  (ordinary Bluetooth-headphone territory) measured as -200 ms, was
  applied, and pushed timing further out, while every tap looked cleanly
  matched. The click is now slower and deliberately uneven -- the
  long-short lilt is on purpose -- which makes that mismatch show up as
  scatter instead of a clean wrong answer. And a result the test cannot
  measure confidently is now REFUSED, with a message naming what it saw
  and pointing at wired audio, instead of applied as a guess. Anyone who
  calibrated on high-latency audio with an earlier build should
  recalibrate, or clear the offset in Settings.

  PRACTICE: SMALLER KITS PILED EVERYTHING ONTO THE HI-HAT
  Picking a smaller kit preset is supposed to fold the hidden lanes into
  sensible neighbours -- toms into a remaining tom, cymbals into the crash.
  The fold tables existed but were never consulted, so every hidden lane's
  notes landed on the hi-hat instead. On the Starter 4 kit, every tom and
  cymbal in a chart played on the hi-hat lane while the lane labelled
  "Toms+Cym" received none of them. The folds now apply; the Standard 8,
  Cymbal Split 10 and Lefty kits hide nothing and are unchanged.

  PRACTICE: THE KIT YOU CUSTOMISED WAS NOT THE KIT YOU PLAYED
  With "(current kit)" selected, every session ran on the stock kit rather
  than the live Kit Studio layout -- and opening Kit Studio after playing
  could then save that stock kit OVER the customised one. Sessions now use
  the tab's own live layout.

  CONTROLS THAT DID NOTHING
  - "Push to Quest" failed on every press -- invisibly in the .exe build --
    which also made its own "convert a song first" guidance unreachable.
  - Practice's Auto-kick toggle (the dock chip and key 3) flipped the label
    but not the running session, so kicks kept being missed and it could not
    be turned back off mid-song.
  - The Synth volume slider did nothing anywhere, and Master never lowered
    synth hits either; synth volume now follows both.
  - Changes in Practice's Settings > Audio did not take effect during play,
    while the dock's own controls did. They now apply immediately.
  - Kit Studio's "Fold into" dropdown was never read at all; it is now
    disabled and labelled "(not wired yet)" instead of looking live.

  SONG TESTER NO LONGER CRASHES ON THE PROBLEMS IT EXISTS TO FIND
  Four kinds of input ended the analysis with a raw Python error dumped into
  the report: silent or unreadable audio (nothing to align against), a chart
  whose notes all sit past the end of the audio (the exact case its own
  duration-mismatch warning describes), a .rlrr with no note events, and a
  valid .rlrr that identifies instruments by index instead of by name. Each
  now stops with a plain explanation, and the Run button recovers instead of
  sticking on "Testing...".

  SONG TESTER HIGHLIGHTS NOW ACTUALLY LAND IN THE EDITOR
  "Highlight in MIDI Editor" could announce "N note(s) highlighted" while
  nothing was outlined: when testing from a .rlrr -- the path the tab calls
  RECOMMENDED -- the tester's timestamps carry the conversion offset and the
  editor's do not, and the lookup demanded an exact match. Flags are now
  matched to the editor's own notes within a tight tolerance, the count
  shown is how many actually landed, and flags that match no note are
  reported instead of silently dropped.

  SONG CREATOR AND PROJECT FILES
  - Opening a .parakit project that omits the difficulty or complexity
    setting -- which is legal -- misnamed the export and then broke Convert
    with an internal error until restart. Both values are now validated;
    the recent-songs list had the same weakness and got the same guard.
  - A song title containing a character Windows forbids in folder names
    (an "AC/DC"-style slash) silently prevented the conversion log .txt
    from being written.
  - An extra stem sharing a file name with the song audio overwrote it
    inside the output pack and appeared twice in the track list. Every
    copied file now gets a unique destination name.
  - Clear All left the Preview Clip and Extra Stem attached even though
    every visible field emptied, so the next Convert copied the previous
    song's files into the new pack.

  ASSET MANAGER
  - An album-art search that errored or found nothing left the PREVIOUS
    song's cover on screen -- and "Apply art" and "Save Image..." then
    silently acted on that earlier song. The preview and the stored result
    are now cleared the moment a new search starts.
  - A clip with a zero or negative Duration was exported as a silent,
    header-only .ogg and reported as saved -- and could then be wired into
    a song pack. It is now rejected before anything is written.

  A FAILED .OGG CONVERSION NO LONGER DESTROYS THE PREVIOUS FILE
  Re-converting a song replaces its existing .ogg -- but the old file was
  emptied BEFORE encoding began, so a failed encode (an FFmpeg build without
  .ogg support, a full disk) left the earlier good file at zero bytes under
  a "Failed" message. Encoding now goes to a temporary file that only
  replaces the real one on success.

  ALBUM ART COULD COME FROM THE WRONG SONG
  Covers extracted from audio tags were cached under the audio FILE NAME
  alone, so two same-named files in different folders -- exactly what the
  stem workflow produces -- shared one cached cover: the last extraction
  won, and the other song exported the wrong art. The cache is now keyed to
  the file's full location.

  REVIEW ISSUES AND SPECTRAL FOLLOW-UPS
  Two rough edges in this release's own fixes: Soften Flams and the cymbal
  Auto Fix answered "No safe fixes were found" when the real cause was a
  stale scan (they now say to rescan, like the other rows), and a Spectral
  Overwrite button disarmed by a newer editor save blamed the file type
  ("not a .mid file") instead of saying why it was disabled.

  TAP TEMPO WAS INVERTED AT CHANGED PLAYBACK SPEEDS
  Tapping a BPM in the MIDI Editor -- the B key, or the tempo-map row's Tap
  button -- while playback was slowed or sped up scaled the result the
  wrong way: tapping along to a 120 BPM song at half speed wrote 30 BPM.
  Only normal speed gave the right number, and the value feeds the tempo
  map, so a chart's timing grid could be warped by it. Both tap paths now
  convert correctly at any playback speed.

  MIDI EXTRACTOR
  - Extract ran on remembered picks, not on the sub-tab on screen -- and a
    single-file pick was never forgotten. Pick one file, switch to Batch
    Folder, pick a folder, press Extract: it re-extracted the single file
    while the batch label still promised a folder's worth. Extract now runs
    whatever the visible sub-tab shows, and says so if nothing is picked
    there yet.
  - An unexpected error mid-run -- a file gone missing, locked, or a
    cloud-synced file failing to download partway through a batch -- ended
    the run silently: no error, no completion, the panel stuck on
    "Running..." with its buttons disabled until ParaKit was restarted. The
    error is now reported (for a batch, with the counts up to that point)
    and the buttons recover.

  SUCCESS MESSAGES THAT WERE NEVER CHECKED
  - The Manual Note Manager's hi-hat save reported "saved to this chart",
    and its Reset reported all lanes reset, whether or not the write to
    disk actually succeeded -- on a read-only folder or a full disk the old
    choices quietly returned on the next load. Both now say when the change
    could not be saved and holds for this session only.
  - Exporting an activity log ("Export Log"), or the Song Tester's fix log,
    to a folder that cannot be written did nothing at all -- no error, no
    file, no confirmation. A failed export now says why and suggests
    another folder.

  HELP DESCRIBED A TAB THAT NO LONGER EXISTS
  The Preview section of Help still documented the retired Visualizer tab:
  it called Preview "visual reference only - no scoring, no input" and
  listed controls that do not exist, while omitting what the tab actually
  has -- including the unsaved-edit prompts added in this very release, and
  stating the audio offset in seconds when the control takes milliseconds.
  Rewritten from the live tab, and Practice is documented as its own tab
  rather than a button that is no longer reachable. Related label fixes:
  the drum separator's "Off" choice no longer claims to be the default;
  Neural Stem Isolation is no longer marked "(experimental)" -- it defaults
  on once installed; Spectral Comparison lost a "New!" badge it had
  outgrown; the YouTube Requirements list now names the JS runtime and the
  Get Deno button; the Review Issues legend names both causes of an orange
  outline; and the save-before-handoff prompts in Preview and Song Creator
  now say that declining cancels, instead of aborting silently.

  THE STEM SEPARATOR SETTING COULD BE IGNORED
  Audio to MIDI read the Neural Stem Isolation choice while the conversion
  was already running, on a different thread from the one that owns it. If
  that read failed the conversion did not stop or warn -- it quietly carried
  on as though the setting were off, producing a different chart from the one
  the setting asked for. The choice is now read once when the conversion
  starts. The separator buttons are also disabled during a run, like every
  other detection setting; they were the only ones still clickable.

  SETTINGS THAT DID NOT STICK
  Several Audio to MIDI settings did not survive a restart the way the
  controls implied. The detection engine and other options could be silently
  reverted at launch to whatever an older saved profile held, and the older
  value was then written back over the newer one. Ride, kick, the separator
  choice and the debug toggle were left out of saved profiles entirely -- and
  the kick and debug settings were not saved anywhere at all, so they reset on
  every launch. Genre profiles promised to remember the engine, ML threshold
  and de-duplication settings but only ever saved three of the five.

  PER-SONG SETTINGS COULD OVERWRITE EACH OTHER
  Audio to MIDI remembers settings per source file, but two files with the
  same name in different folders -- or the same song as .wav and .flac --
  shared one entry, so opening the second silently replaced the first's saved
  settings. Each file now gets its own; anything already saved still loads.

  v4.9.8   --   2026-07-31
------------------------------------------------------------------------------
  Four bugs in the MIDI Editor and the Chart Troubleshooter, and a setting
  that now remembers itself. All four bugs were present in every 4.9.x build.

  DIFFICULTY TIERS NO LONGER STACK ON TOP OF EACH OTHER
  Reducing a chart to Medium, saving it, comparing, and then reducing to Hard
  produced a Hard chart SPARSER than the Medium it came from -- 103 notes
  where reducing straight to Hard gives 172, against Medium's own 107. The
  status line reported it as a normal Hard chart.

  The cause: compare mode finishes by loading the reduced chart as the working
  chart, and that load cleared the record of what the ORIGINAL chart was. The
  next reduction then measured against the already-reduced chart instead. The
  original is now restored as the baseline after a compare, so every tier is
  cut from the full chart no matter how many you audition first.

  This is the same stacking problem the v4.9.6 fix addressed, reached through
  a different route -- the save-and-compare flow, which is the normal way to
  try tiers out.

  THE WAVEFORM COULD BELONG TO THE PREVIOUS SONG
  Loading a new stem into the MIDI Editor could leave the OLD song's waveform
  drawn underneath the new song's name. Notes are aligned against that
  waveform, so the picture used for lining up a chart could quietly be the
  wrong song's. The cached waveform is now cleared whenever audio is loaded.

  CHART TROUBLESHOOTER: DUPLICATE AND BREAK CHECKS WERE MEASURING IN SECONDS
  The duplicate-note check was meant to look within 20 milliseconds and the
  long-break check within 500 milliseconds. Both were reading those numbers as
  SECONDS. At 120 BPM a 20-second window spans about 160 sixteenth notes, so
  practically every note that shared a lane with any neighbour was reported as
  a duplicate, and the 500-second break check never fired at all. Long charts
  also scanned much more slowly than they should have. Both windows now use
  the units they were written for.

  ONE DRAWING ERROR NO LONGER ENDS PLAYBACK FOR THE SESSION
  If anything went wrong while drawing a frame during MIDI Editor playback,
  the view stopped updating for the rest of the session while the audio kept
  playing, the editor never noticed the song had ended, and a playback
  optimisation was left switched on that no other tab could clear. Drawing
  errors are now contained: playback keeps running, the view recovers on the
  next frame, and a one-time notice appears in the status line.

  REACTIVE NOTES REMEMBERS YOUR CHOICE
  The Reactive Notes checkbox and its Style dropdown now persist between
  launches. v4.9.7 made the new glow the default, so anyone who preferred
  "Flash Notes (Classic Style)" had to pick it again on every start.

  ALSO
  "Cancelled" is now spelled "canceled" in eight status and log messages, for
  consistency with the rest of the app.

  v4.9.7   --   2026-07-29
------------------------------------------------------------------------------
  Two MIDI Editor changes: picking a chart now opens it, and the notes that
  light up during playback keep their lane color instead of flashing white.

  PICKING A CHART OPENS IT
  Choosing a MIDI file in the MIDI Editor filled in the path but drew nothing
  until "Load MIDI" was pressed, so on a cold start the editor sat empty and
  looked broken. Picking a file now opens it straight away -- by Browse, by
  drag-and-drop, or from the recents menu.

  This only happens when the editor is empty. With a chart already open,
  nothing loads until "Load MIDI" or "Reload" is pressed, so unsaved edits are
  never swapped out from underneath you. "Load MIDI" is now only needed to
  REPLACE an open chart, and its tooltip says so.

  REACTIVE NOTES: A NEW GLOW STYLE
  Reactive Notes used to blank each note solid white as the playhead crossed
  it, which meant losing track of which drum it was at exactly the moment it
  mattered. Notes now flare to a brighter version of their OWN lane color and
  throw a soft halo that fades out behind them, so a note stays identifiable
  while it lights up.

  The original white flash is unchanged and still available -- it is now
  called "Flash Notes (Classic Style)" in a Style dropdown under the Reactive
  Notes checkbox. The new glow is the default.

  v4.9.6   --   2026-07-28
------------------------------------------------------------------------------
  Converting a FULL MIX now works properly, and difficulty reduction moved
  into the MIDI Editor where you can see what it did.

  FULL-MIX CONVERSIONS ARE FIXED
  Feeding Audio -> MIDI a whole song instead of a drums-only stem used to
  roughly DOUBLE the kick lane and lose most of the hi-hats. The cause was
  routing, not detection: the drum separator splits drums into their parts and
  has nowhere to put bass or vocals, so a full mix's bass was pushed into the
  drum stems and the low end landed on KICK. The app now recognises a full mix
  and splits it FIRST, then hands the drums stem to the separator. On two test
  songs the kick count went from 1225 and 1161 down to 522 and 498, against
  clean drums-stem references of 530 and 453. Scored against 334 human-charted
  songs the corrected route measures 0.835 where the old one measured 0.418.

  Nothing changes for the recommended workflow -- splitting the song yourself
  in the Stem Splitter and converting the drums stem is still the best chart --
  but converting a full mix is no longer a trap.

  The detector is now also biased toward treating an ambiguous input as a full
  mix. Guessing "full mix" when it was really a drums stem costs almost nothing
  (measured across 35 songs: no song got worse by more than a rounding error).
  Guessing the other way leaves a song on the broken path. The two mistakes are
  not equally bad, so the app leans toward the harmless one.

  DIFFICULTY REDUCTION MOVED TO THE MIDI EDITOR
  Thinning a chart to Easy, Medium or Hard used to happen invisibly while the
  song was built, so the only way to see the result was to import the finished
  file and look. There is now a "Difficulty" button on the MIDI Editor toolbar.
  Pick a difficulty, then either apply it to the open chart (Ctrl+Z undoes it),
  save it as a separate chart file, or save it and load it back with the
  original shown behind it as a ghost overlay so the two can be compared in one
  click.

  Picking a different difficulty afterwards re-targets from the original chart
  rather than thinning what is already thinned, so choosing Hard after Medium
  gives a real Hard chart instead of something sparser than Medium. The old
  "Enable difficulty-based note reduction" checkbox in the Song Creator tabs is
  gone; difficulty there is now a label only.

  The "Re-run ML" button was removed from the MIDI Editor. To re-run detection,
  convert the song again on the Audio -> MIDI tab.

  ALSO IN THIS RELEASE
  - "Remove cross-stem bleed kicks" now describes what it is actually for. The
    check is precise: some "kicks" are really the bass guitar leaking into the
    drums track, and this pass compares each kick against the song's bass,
    vocals and other parts to find them. It only deletes clear-cut cases and
    flags the rest in the MIDI Editor. It is still EXPERIMENTAL and still needs
    the full mix, but with the routing fix above that no longer costs you chart
    quality, and it now reuses the split instead of separating the song twice.
    A drums stem from the Stem Splitter remains the better input.
  - Practice no longer claims Mute-on-Miss is working when it cannot. The
    in-session dock now shows it as unavailable instead of silently doing
    nothing when the loaded audio cannot support it.
  - Long tooltips wrap instead of running off the edge of the screen.
  - The dependency list shipped in the repo root was the wrong one (it listed
    the in-progress v5 rebuild's requirements), so a fresh install could pull
    packages ParaKit v4 does not use. It now lists v4's actual dependencies.
  - Two temp-folder leaks in the new full-mix split are closed; a failed split
    used to leave several full-length audio files behind every time.
  - Assorted wording fixes across the app's labels and help text.

  v4.9.5   --   2026-07-27
------------------------------------------------------------------------------
  Practice's audio panel now tells the truth about "You drum" / Mute-on-Miss.

  The problem: both features work by muting the recorded drum stem, so they can
  only do anything when the other linked file is a DRUMLESS backing. Plenty of
  charts instead link a full mix plus a drum stem -- and muting the drum stem
  cannot remove drums that are already baked into the full mix. Practice showed
  the same "You drum (Mute on Miss)" switch either way, so on those songs the
  toggle looked available, did nothing audible, and gave no clue why. Picking
  "Backing + Drums" on one of those songs also layered the drum stem on top of a
  mix that already had drums, which doubles them and sounds bad.

  What changed:
  - Practice now states plainly, before you press play, when "You drum" and
    Mute-on-Miss cannot work for a song -- and which of the two reasons applies:
    no drum stem is linked at all, or the linked backing is really a full mix
    with the drums baked in.
  - The source button is named for what it would actually play. On a chart whose
    backing is really a full mix it now reads "Full Mix + Drums (not recommended
    -- doubles them)" instead of "Backing + Drums", which claimed a drumless
    backing the song does not have.
  - The audio readout says "1 linked full mix" rather than "1 linked backing"
    for those charts, and no longer offers to turn "You drum" off "to hear the
    full backing drums" when those drums cannot be muted.

  Nothing about playback or audio routing changed -- Auto already picked Full Mix
  on these songs to avoid the doubling. This release is about the app no longer
  presenting a control that cannot do anything, and naming each linked file
  correctly.

  Also in this release: "Remove cross-stem bleed kicks" is now marked
  EXPERIMENTAL.
  - That option only finds anything when the conversion input is a FULL MIX, and
    converting from a full mix currently produces a clearly worse chart than
    converting from an already-split drums stem -- noticeably more phantom kicks.
    So switching it on to clean up kicks can leave the chart worse overall than
    leaving it off.
  - The option now says so: an EXPERIMENTAL tag on the checkbox, a visible note
    under it, and an expanded tooltip. It is still useful in some cases for
    spotting ghost kicks for review, but it is not a way to get a better chart.
  - The recommended workflow is unchanged and is now stated on-screen: split the
    song first, convert the drums stem, and leave this off.
  - The option itself is untouched and still defaults to off; only its labelling
    changed.

  Also fixed: in the Spectral tab, the per-lane "Notes" toggle did nothing
  while Edit mode was on.
  - Edit mode needs the notes on screen to click them, so it deliberately keeps
    Notes turned on. But it did that silently: the button stayed lit and
    clickable and simply ignored you. It now greys out while Edit is on, so it
    is clear the toggle is locked rather than broken, and its tooltip says to
    turn Edit off to hide the notes.
  - The Bars toggle was never involved, despite appearances -- Notes works
    normally with Bars on or off.

  Also fixed: songs downloaded from a YouTube playlist no longer arrive with
  " - Topic" stuck on the artist.
  - YouTube auto-creates a channel per artist named literally "<Artist> -
    Topic", and a playlist download reports that channel as the artist. The
    suffix is now removed as the download is filed.
  - Only that exact suffix is removed. An artist genuinely called Topic still
    works, "Off Topic" is left alone, and names containing hyphens such as
    Blink-182 are untouched.
  - This applies to new downloads. Songs already in the library keep whatever
    artist they were filed with.

  v4.7.26   --   2026-07-16
------------------------------------------------------------------------------
  One release, three hardening rounds. After 4.7.25 shipped we pointed three
  independent automated "breakers" at ParaKit -- programs whose only job is to
  make the app misbehave by actually running it -- then fixed everything they
  proved, and re-ran them on the fixes, three rounds deep. Twelve distinct
  bugs were found and fixed this way, most of them the quiet kind you would
  never see in a log: files silently overwritten, a save that could destroy
  your work, a "success" message standing on nothing. None of them changes
  detection results or charting.

  MIDI Editor -- your chart is now safe to save, no matter what:
  - FIXED: a save that failed part-way (disk full, an antivirus or sync tool
    stalling the write, a crash) could DESTROY the chart you were saving --
    the file on disk was truncated to a useless stub, taking an editing
    session's hand-fixes with it. The save is now atomic: ParaKit writes a
    complete replacement next to your file first, and only swaps it in once
    it is fully on disk. If anything goes wrong mid-save, the file you had is
    untouched, and "Save Failed" now means exactly that -- nothing was lost.
  - FIXED (a bug the atomic save itself introduced, caught by the next breaker
    round): with the swap-in approach, a backup tool / sync client / indexer
    merely holding your chart open could make the final swap fail -- so a save
    Windows would happily have accepted was refused, with your edits stranded
    in the editor. ParaKit now detects that specific refusal and falls back to
    writing the already-complete data directly over the file, so the save
    lands either way. You keep both guarantees: a failed save never destroys
    the chart, and a save the system permits actually saves.

  Audio -> .ogg Converter -- the count you're shown is now the files you have:
  - FIXED: converting two files with the same name (think "01 Intro.wav" from
    two different albums, or the "drums.wav" every stem-split folder contains)
    silently collapsed them into ONE output file -- the second overwrote the
    first, and the dialog still said "2 file(s) converted successfully!". One
    of your songs was just gone. Same-named files in a batch now come out as
    "01 Intro.ogg" and "01 Intro (2).ogg", the rename is noted in the log, and
    the completion count always matches what is actually on disk.
  - FIXED (follow-up the breakers forced on the fix above): a "(2)" file
    created by an EARLIER batch could still be silently replaced by a later
    batch's rename. Collision renames now only ever CREATE new files -- the
    only file a conversion will overwrite is the plain "<song>.ogg" of the
    song you are deliberately re-converting.

  Create Multiple Songs (batch):
  - FIXED: a song whose chart came out with zero playable notes (for example
    a bad manual offset pushing every note before the start) was still written
    to disk, audio copied in beside it, and counted into "N/N songs converted
    successfully" -- a folder that looks like a song and plays as nothing. The
    batch now refuses it with the same "ERROR: No events generated. Check MIDI
    file and BPM." message the Single Song Creator has always shown, and it
    counts as a failure, not a win. (A Clone-Hero-only song with no drum
    events likewise no longer counts as converted.)

  YouTube -> FLAC library -- album art undo:
  - FIXED: "Undo album art search" could put a DELETED song's cover into a
    completely different song. The undo backup was tied to the file's PATH,
    and paths get reused: delete a download, later download another version of
    the same track (same title -> same filename), and the old backup was still
    offered -- and silently embedded the dead song's art into the newcomer.
    The undo backup is now removed together with the song, whether you delete
    it from disk or just remove it from the library list -- and if something
    on your PC (an antivirus scan, a thumbnailer, the search indexer) happens
    to be holding one of the backup files open at that exact moment so it
    cannot be deleted, ParaKit marks it dead instead, so the stale undo can
    never be offered. A fresh art search on the new song re-enables Undo
    normally.

  Clone Hero export:
  - FIXED: a song whose title contained a line break (which can arrive
    automatically -- ParaKit can fill the title from an audio file's own tags,
    and some files carry a stray newline in there) produced a broken Clone
    Hero pack. The line break split the song-info block, so Clone Hero either
    refused the song or read its details wrong -- and ParaKit still said
    "converted". Titles are now cleaned of line breaks before the .chart and
    song.ini are written; ordinary titles (quotes, apostrophes, symbols) are
    unaffected.

  Song Tester:
  - FIXED: loading a MIDI or .rlrr with no notes in it crashed the analysis
    with a raw error traceback in the Tester log. It now tells you plainly
    that there is nothing to analyze and to check you picked the right file.

  Audio -> MIDI -- ML / Hybrid model checking (completing 4.7.22-4.7.25's work):
  - FIXED: the model status could still lie in one remaining direction. 4.7.25
    made sure a GOOD model is never marked bad by a moment's interference; the
    mirror case survived -- a model that had genuinely gone bad ON DISK (the
    file replaced in place at the same size, as cloud-sync placeholder and
    restore operations do) could keep its green "Model ready" tick for the

  - Also from this work: "couldn't check just now" (file busy) is shown as its

  - Under the hood: ParaKit's self-test suite grew from 10 to 38 executable
